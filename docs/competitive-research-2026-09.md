## (a) 各プロダクトの概要

### Viktor (viktor.com)
- **立ち位置**: 「Not a tool. A hire.」Slack / Microsoft Teams（2026-06 GA）/ Discord（2026-08）に常駐する「AI 社員」。チームで 1 体を共有する。2026-02 ローンチ、60,000 超のワークスペース、G2 4.8/5（35件）、ARR 約 $29M（2026-08）。[viktor.com](https://viktor.com/) / [Product Hunt](https://www.producthunt.com/products/viktor) / [thisandthat.chat](https://www.thisandthat.chat/blog/viktor-review-2026/)
- **実行モデル**: @Viktor で呼ぶと、専用のクラウドコンピュータを立ち上げてコードを書いて動かし、3,200 超のツールを操作する。成果物は PDF・スプレッドシート・Web アプリ（Spaces / Pages）・PR。[eesel.ai](https://www.eesel.ai/blog/viktor-ai-review)
- **定期実行**: スケジュールタスク（cron）。UI から作成（2026-06）、一時停止・再開、タスクごとのコスト内訳、完了時の @mention 通知、送信者名のカスタマイズ。[changelog](https://viktor.com/changelog)
- **記憶**: 会話やワークフローを観察して「skills」（内部ノート）に書き残す。Skills ページはツリー＋リーダー表示で、使用頻度順に並ぶ。アップロード・編集・ダウンロードができ、共有 skill はスラッシュコマンドとして呼べる。メンバーごとの個人 skill もある。「Clean Workspace」で全消去。Supermemory 連携。[viktor.com](https://viktor.com/)、[changelog](https://viktor.com/changelog)
- **能動性**: 「頼まれていない自動化を提案する」のがレビューで一番評価されている。一方で「メッセージが届いても何も自動では始まらない（呼ぶかスケジュールだけ）」「受信メールに反応できない」という批判もある。[thisandthat.chat](https://www.thisandthat.chat/blog/viktor-review-2026/)
- **信頼・承認 UX**:
  - メール送信や本番デプロイなど、影響の大きい操作の前に確認を取る。
  - 承認カードは平易な一文を先頭に出し、JSON はトグルの奥に隠す（2026-09-07）。
  - 複数の承認をまとめて出す（2026-08-31）。
  - 「このツールは常に承認」（Slack 2026-04、モバイル 2026-09-24）。
  - 作業中に話しかけると短いステータスを返す。実行中の追加指示は「キューに入れる」か「実行中のターンに割り込ませる」かを選べる（2026-09-09）。
  - Slack Connect の外部チャネルでは DM に引き取って承認を取る。
  - 監査ログ（Enterprise）。[changelog](https://viktor.com/changelog)
- **オンボーディング**: アプリディレクトリからインストール → ツール接続（約2分）→ Viktor が自己紹介して「何を手伝いましょう？」と聞く。
  - Web セットアップで参加するチャネルを選ぶ。
  - skill を入れた後にツール設定のチェックリストを出す。
  - OAuth が終わると会話が自動で再開する。
  - 壊れた連携はワンクリックで再接続。[changelog](https://viktor.com/changelog)
- **Web アプリ（2026-07〜09 に急拡張）**:
  - Web チャット、⌘K（ナビゲーション＋履歴検索＋新規チャット）、過去の会話の全文検索、スレッドの自動タイトル、スレッド行の未読バッジ。
  - アーカイブ、スラッシュコマンド、キーボードショートカット一覧ページ、サイドバーの折りたたみ（⌘B）。
  - チャット幅の設定、絵文字検索、個人ダッシュボード（最近のチャット・スケジュール実行・公開ページ）。
  - 28 言語対応、音声（読み上げ・文字起こし・話し始めたら読み上げを止める）。
  - MCP サーバー、OpenAI 互換 API。[changelog](https://viktor.com/changelog)
- **料金**: 無料クレジット $100（カード不要）→ Team $50/月（20,000 クレジット、シート課金なし）→ Enterprise。
  - 目安は小タスク 100〜300、複雑なワークフロー 500〜1,500、プロジェクト 2,000〜5,000 クレジット。
  - 自動チャージ、利用 API、Enterprise の月額上限、モデル選択画面でのコスト見積もりがある。[eesel.ai](https://www.eesel.ai/blog/viktor-ai-review)
- **不満**: クレジットの減りが読めない（「2日で $200」、Trustpilot 3.4）、機能が分かりにくい、複雑なタスクで遅い、チャネルを跨ぐと文脈が消える、「自動化の判断が見えにくい」、冗長。[Product Hunt](https://www.producthunt.com/products/viktor)、[thisandthat.chat](https://www.thisandthat.chat/blog/viktor-review-2026/)

### Ando (ando.so)
- **立ち位置**: 「The modern team messaging platform」。Slack をゼロから作り直し、エージェントを最初から「一級市民」（人と区別されない同僚）として扱う。CEO は Sara Du（元 Alloy Automation）。出資は Accel / Index / Emergence。現在は非公開アルファで、ウェイトリスト制（新しい会社は 24 時間以内に招待される枠あり）。30 人程度までのチーム向けで、料金は非公開。[ando.so](https://www.ando.so/)、[New Ontologies](https://www.new-ontologies.com/posts/Ando)、[Index](https://www.indexventures.com/companies/ando/)
- **機能（公表されているもの）**:
  - チャネル・スレッド・DM（Slack と同じ機能は「揃えるから信じて」という姿勢で、機能一覧をあえて出していない）。
  - **Jams**: ハドル相当の音声・ビデオ。会話はすべて文字起こしされ、テキストと一緒に索引化される。
  - **Clips**: 別々のスレッドからメッセージを切り抜いて、エージェントに渡す文脈を組み立てる。
  - **Conversational units**: エージェントがメッセージをまとめてラベルを付け、検索の精度を上げる。
  - Ando 製・自作・サードパーティのエージェントを同じように参加させられる。Slack 連携は一時的に残している。[New Ontologies](https://newontologies.substack.com/p/ando-building-slack-from-scratch)
- **プライバシー**: エージェントは DM を読めない。本人が転送したときだけ読める。
- **注意（attention）設計**: 通知をまとめ、「他人の都合に振り回されない」ようにする。Tadao Ando の「間」、つまり静けさを価値として扱う。エージェントの文体は Hemingway 基準（短く正確に）。
- **事例**: Truth Systems は、Jam で設計を議論する → エージェントが文字起こし・過去の良いチケット・コード・Linear 履歴から実装できるチケットを起こす、という流れでチケットの起票と完了を 100% Ando に移した。

### Slack（比較の基準）
- Slack Help Center の機能群（[slack.com/help](https://slack.com/help)、[slack.com/features](https://slack.com/features)）。以下は公開ヘルプの一般的な機能セットからまとめたもの。
  - メッセージ: 編集・削除、スレッド（チャネルにも投稿するオプション付き）、リアクション、ピン留め、ブックマーク。
  - 後で見る: Later（保存＋リマインド）、/remind、下書き＋送信済み一覧、予約送信。
  - 未読: 未読のみ表示、Alt+クリックで未読に戻す、All unreads、Activity（メンション・リアクション・スレッド）。
  - 検索: from:/in:/on:/before:/after:/has:link 等のフィルタ。
  - 共同作業: ハドル、クリップ（音声・動画）、Canvas、リスト、ワークフロービルダー。
  - 人: ステータス（絵文字＋期限）、在席・離席・おやすみモード、通知設定（チャネル単位・キーワード）。
  - 操作: ⌘K（ジャンプ）、⌘/（ショートカット一覧）、↑で直前のメッセージを編集、Esc で既読、⌥↑↓ でチャネル移動。
  - その他: プロフィール（肩書・現地時刻・連絡先）、ユーザーグループ（@team）、ファイルのプレビュー、リンク展開、コードブロック・書式ツールバー、メッセージのリンクをコピー、転送（Share）。

## HonmaruAI の現状（コードから確認したこと）

- **チャネルの API**（`worker/src/channelRoutes.js`）: `GET /channels`、`GET/POST /channels/messages`（`before` でページング可、1 ページ 150 件）、`POST /channels/decide`。
  - @AI が入っているか「Make it a decision」を押すと判断カードになり、周りの会話がカードの文脈になる。
- **未コミットの作業**: `worker/src/channels.js` と `schema.sql` / `migrations.sql` に、編集・削除（返信があれば墓標として残す）・スレッド（`parent_id`）・ピン・メッセージへのリアクション（`message_reactions`）が入っている。
  - ただし `channelRoutes.js` にルートがなく、`ClassicList.tsx` にも UI がない。**バックエンドの途中段階**で、他の作業と衝突しないよう注意が要る。
- **カード側にはある**: カードのコメント（`/cards/:id/comments`）とリアクション（`/cards/:id/reactions`、`threads.js`）。
- **既読管理**（`ClassicList.tsx` の `seenKey`）: **localStorage 上の「最後に見た時刻」**だけで管理している。
  - サーバーに既読位置がないので、端末間（PC ↔ スマホ）で同期されない。メンション一覧（Activity）もない。
- **メッセージの読み込み**: 開いたときに 1 回 fetch するだけで、以降は CustomEvent（WebSocket 経由）で追記する。
  - クライアントは `before` を使っていないので、**150 件より古いメッセージを遡れない**。
- **検索**: `/search` は判断カードのみが対象（`searchDecisions`、12 件）。メッセージは検索できない。
- **ショートカット**: ⌘K パレット、`n` で新規作成、フィードの j/k/a/d（`Dashboard.tsx`、`Feed.tsx`）。
  - Enter で送信、Shift+Enter で改行、IME 変換中は送らない配慮がある。⌘/ のショートカット一覧はない。
- **空状態**: チャネル冒頭の「This is the start of #name」説明、`No decisions here yet.`、セクションごとの `cl-empty` がある。
- **オンボーディング**（`Onboarding.tsx`）: 3 ページの説明＋役割＋言語だけ。「使いながら学ぶ」設計。デモカードをスワイプする。
- **既にある差別化要素**: Routines、Proposals、Playbook、MCP、コスト表示。詳細は `docs/viktor-gap-plan.md`。

## (c) 優先改善提案トップ 15

工数は S = 1〜2 日、M = 3〜7 日、L = 2 週間以上。

1. **メッセージの編集・削除・スレッド・リアクション・ピンを仕上げる（Must, M）**
   - 未コミットの `channels.js` の内容に `PUT/DELETE /channels/messages/:id`、`GET /channels/threads/:id`、`POST /channels/messages/:id/reactions`、`POST /channels/messages/:id/pin` を足して公開する。
   - UI: ホバーで右上にツールバー（😀 リアクション / 💬 スレッド / 📌 / ⋯ 編集・削除・リンクをコピー・判断にする）。スレッドは右ペイン（今はカード詳細のペイン。タブを共有する）。
   - 編集した判断元メッセージは「カードに反映しますか？」と提案する（Viktor の「編集で再応答」）。
2. **既読をサーバーで同期する＋Activity 受信箱（Must, M）**
   - `channel_reads(org, login, channel, last_read_at)` を追加。サイドバーに「未読」「メンション」「スレッド」をまとめた Activity を置く。
   - Esc で既読、Alt+クリックで未読に戻す。スマホ（スワイプ）と PC の未読を一致させる。
3. **過去メッセージの無限スクロール＋「新着はここから」線（Must, S）**
   - 上端に来たら `before=` で読み込む。前回の既読位置に赤い「New」区切り線を出し、スクロール位置を保つ。
4. **メッセージ＋判断の統合検索（Must, M）**
   - ⌘K の中で `from:@yuki in:#hotel has:decision before:2026-09-01 is:waiting` のようなフィルタチップを使えるようにする。
   - 結果はメッセージ・カード・Playbook を種類別に並べ、ヒット箇所をハイライトする。D1 の FTS5 を使う。
5. **AI の作業を見せる（Must, S〜M）**
   - @AI の直後に「読んでいます → 担当者を決めています（#hotel の過去 3 件から @yuki）→ カードを作りました」という段階表示を出す。完了したらメッセージに ✅ リアクションと「→ 判断」のリンクを付ける。
   - 「なぜこの人に？」を 1 行の根拠として出す（Playbook のルール名にリンク）。Viktor が「判断が見えない」と批判されている点への答えになる。
6. **最初の 5 分で実カードを出すオンボーディング（Must, M）**
   - 役割を聞いた後に「Gmail をつなぐ（推奨）/ チームを招待 / 最初の一言を AI に」のチェックリストを出す。
   - 接続したら直近の 24 時間を取り込み、**本物の判断カードを 3 枚**見せる。OAuth が終わったら元の画面に戻る（Viktor の auto-resume）。
   - Welcome ではチャネル `#general` と AI からの自己紹介メッセージを最初から置いておく（空の画面を出さない）。
7. **「常に承認」→ Playbook ルール化＋まとめて処理（Should, M）**
   - 同じ種類のカードを 3 回続けて承認したら、カードに「次から自動承認しますか？（上限 ¥30,000 まで）」を出す。承認すると Playbook のルールになり、取り消せる。
   - 同じ送り主・同じ種類のカードを束ねて「3 件まとめて承認」できるようにする。
8. **Clips: 会話を切り抜いて判断にする（Should, M。差別化になる）**
   - 複数のメッセージ（別チャネルも可）をチェックして「これで判断を作る」。
   - 選んだものがそのままカードの文脈（出典リンク付き）になる。Ando の Clips を判断の形に置き換えたもの。
9. **下書きの保持＋予約送信＋ Later（Should, S〜M）**
   - チャネルごとに下書きを保存し、サイドバーに ✏️ を出す。送信ボタンの横に「予約送信」。
   - メッセージの ⋯ から「後で（1時間 / 明日 9時）」で Later リストに入れ、時刻が来たら通知カードとして戻す（既存の `later` の流れを使う）。
10. **スラッシュコマンド（Should, S）**
    - `/decide @yuki 見積もりの承認`、`/routine 毎週月曜9時に…`、`/remember 5万円以下は経理判断`、`/remind`。
    - 入力中に補完メニュー（`MentionMenu` と同じ仕組み）を出す。
11. **ステータスと不在時の代理（Should, M）**

## (d) コードから読み取れる UI の品質課題と機会

**PC 最適化**
- `ClassicList.tsx` は 955 行の単一コンポーネント。スレッドやツールバーを足す前に、Sidebar / Conversation / Composer / DetailPane に分けておかないと保守できなくなる。
- 幅の判定が `WIDE = (min-width: 720px)` の 1 段階だけ。1280px 以上ならカード詳細・スレッド・メンバー情報の 3 ペイン、720〜1280px ならオーバーレイ、というように段階を増やせる。
- リサイズできるペインや折りたたみ（⌘B）がない。
- メッセージのホバー操作が「Make it a decision」だけ。Slack 利用者が期待するホバーツールバーがない。

**リアルタイム性と信頼性**
- 既読が localStorage に依存している。シークレットモードや別端末では全部が未読扱いになり、バッジが信用できなくなる。
- メッセージは最初に 150 件取るだけで、再接続時の差分取得もない。WebSocket が切れている間のメッセージは再読み込みするまで見えない。オンライン復帰時に `after=` で取り直す仕組みが必要。
- 送信は楽観的更新ではない（`res.ok` を待ってから下書きを消す）。失敗時の「再送」ボタンと送信中の表示がない。

**空状態**
- 「No decisions here yet.」は何をすればよいかを示していない。
  - 例: 「ここに @AI と書けば判断になります」＋サンプル文をボタンにする（押すと composer に入る）。
- Apps セクションに何も接続されていないときは、Tools の接続画面へのショートカットを置く。
- DM が空のときは、メンバー一覧から「@yuki に話しかける」を出す。

**オンボーディング**
- `Onboarding.tsx` は説明＋役割＋言語だけで、接続・招待・最初のカードまで導かない。
- 「使いながら学ぶ」思想は正しいが、**最初の実データ**がないと価値が伝わらない（Viktor は 2 分で接続→自己紹介）。
- 初回セッションの間、サイドバー上部に進捗チェックリスト（3/5）を出す。

**AI の可視性**
- 「Your AI is making a decision card…」の単一表示だけで、失敗時はメッセージで謝るだけ。段階表示・所要時間・「キャンセル」がない。
- カードに「どのメッセージ・どの Playbook ルールから作ったか」の出典チップを付けると、信頼が大きく上がる。

**アクセシビリティと i18n**
- `aria-label` は丁寧に付いている。
- ホバーでしか出ない操作を増やすときは、キーボードフォーカスでも出るよう `:focus-within` を必ず付ける。
- 日付区切り（Today / Yesterday）はロケールに対応済み。予約送信やリマインドを足すときは、タイムゾーン（IANA）を routines と揃える。

**その他**
- `/search` は判断カードのみ 12 件。「もっと見る」もフィルタもないので、PC 利用者の探す体験が弱い。
- カードのコメント（`threads.js`）とメッセージのスレッド（`parent_id`）の 2 系統ができかけている。UI 上は「スレッド」として 1 つに見せる方針を先に決めておくべき。
