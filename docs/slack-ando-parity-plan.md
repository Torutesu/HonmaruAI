## 2. このブランチで入れるもの（P0）

### 2.1 モバイル（リスト表示、幅 720px 未満）

- **下のタブ**
  - ホーム（チャネル・DM・アプリの一覧）、DM、アクティビティ、後で、あなた の 5 つ。
  - カード表示の下のタブは今のまま。リスト表示の時だけこのタブに替わる。
  - アクティビティのタブには、未読の数をバッジで出す。
- **新規メッセージの丸ボタン**: ホームと DM の右下に置く（Slack の ✏️ と同じ位置）。
  - 押すと「AI に伝える」「メッセージを送る相手を選ぶ」を選べる。後者は、グループ DM も作れる相手選び。
- **DM タブ**: 一人ひとりの顔、名前、最新メッセージの 1 行、時刻を並べる。未読は太字にする。
- **会話のヘッダー**
  - 左から: 戻る、名前（1 行、あふれたら省略）、その下に人数または「N 件の決定」。
  - 右は通話と ⋯ だけ。コンテキスト、自動化、メンバー、ピンは ⋯ から開く（Slack と同じく、名前をタップしても詳細が開く）。
- **長押しのアクションシート**
  - タッチ端末では、マウス用の浮くツールバーを出さない。
  - メッセージを長押しすると、下からシートが出る。中身は:
    - よく使うリアクション 6 つ
    - スレッドで返信
    - テキストをコピー
    - リンクをコピー
    - 後で見る
    - ピン留め
    - 決定カードにする
    - 編集・削除（自分のメッセージだけ）
- **入力欄**
  - 1 行目: 本文。
  - 2 行目: 左に ＋（写真・ファイル）、右に送信。
  - 「決定カードとして送る」は送信ボタンの長押しと ▾ に移し、幅を取らない。
- **安全域**: 下のタブと入力欄に `env(safe-area-inset-bottom)` を入れる。iPhone のホームバーに重ねない。

### 2.2 ファイル・画像の添付

- **添付する方法**: 入力欄の ＋、貼り付け、ドラッグ＆ドロップ、スマホのカメラロール。
- **1 通の上限**: 10 ファイル、1 つ 25 MB まで。
- **保存と配信**
  - 保存先は R2（`MEDIA`）で、オブジェクト名は `file-<uuid>`。
  - `message_files`（メッセージ ID、名前、型、サイズ、幅・高さ）に記録する。
  - 配信は `GET /files/:id`。**そのメッセージを読める人だけ** が取得できる（DM の外や、非公開チャネルの外からは 404）。
  - 次の型は `Content-Disposition: attachment` で返す。同じオリジンで HTML を実行させないため（`media.js` と同じ考え方）:
    - HTML
    - SVG
    - その他、画像・動画・PDF 以外の型
- **表示**
  - 画像はタイムラインに縮小表示し、タップで全画面（ライトボックス）にする。
  - それ以外はファイル名・種類・サイズのチップにして、タップでダウンロードする。
- **AI**: 添付の名前と種類は AI に渡る会話の文脈に入れる（「〜.pdf を添付」）。中身の解析は後で考える。

### 2.3 グループ DM（3〜9 人）

- **保存キー**: `dm:<login>|<login>|<login>`（ソート済み）。2 人の DM と同じ仕組みを広げる。
- **ブラウザでの名前**: `dm:<ref>,<ref>`。自分以外の人の handle を並べ、ログインは出さない。
- **読める人**: キーに含まれる人だけ。一覧、検索、Activity、既読、通話のすべてで同じ判定をする。
- **表示**
  - サイドバーの「ダイレクトメッセージ」に、重なった顔と「A、B、C」で並ぶ。
  - 新規メッセージの相手選びで複数を選ぶと作られる。

### 2.4 非公開チャネル

- **データ**
  - `businesses.private`（0 / 1）を足す。
  - `channel_members(org_id, slug, login, added_by, added_at)` を足す。
- **作る**: チャネル作成で「非公開」を選ぶ。作った人が最初のメンバーになる。
- **メンバーの追加・削除**: メンバーなら誰でもできる（Slack の既定と同じ）。
- **読める人**: メンバーだけ。メンバーでない人には存在も見せない（一覧に出ない、`b:<slug>` は 404）。
- **判定する場所**
  - `resolveChannel`、`viewOf`、一覧・検索・Activity の SQL
  - リレーの配信（`OrgRelay` がメッセージを流す相手）
  - Webhook の配信範囲
  - 決定カードの表示範囲
- **表示**: サイドバーでは `#` の代わりに鍵のアイコンを出す。

## 3. 次にやるもの（P1、別ブランチ）

1. **通知の一時停止とスケジュール**
   - 「1 時間 / 今日の終わりまで / 明日の朝まで」の一時停止と、曜日ごとの通知時間帯。
   - サーバーの push 判定でも守らせる。
2. **PC で操作中はスマホに通知しない**
   - `OrgRelay` が最後に操作した時刻を持つ。
   - 操作中なら、APNs と Web Push を 2 分待ってから送り、その間に読まれたら送らない。
3. **スレッド一覧**: 自分が書いた、またはメンションされたスレッドを、最新の返信順に並べる。
4. **未読にする、転送**
   - 未読にする: 既読位置を、そのメッセージの直前に戻す。
   - 転送: 引用付きの新しいメッセージにする。元が非公開なら「リンクのみ」にする。
5. **サイドバーのセクション**: 自分だけのフォルダとお気に入り。
6. **ユーザーグループ**: `@営業` で全員にメンションする。
7. **Guest の役割、セッション管理、監査ログ Phase 1**: [enterprise-audit-log.md](enterprise-audit-log.md) の §11。
8. **API キーのスコープと Provisioning キー、Webhook の配信ログと再送。**

## 4. 確かめ方

- **ユニットテスト**
  - worker:
    - 非公開チャネルとグループ DM で、読める・読めないの判定表（一覧 / 1 件 / スレッド / 検索 / Activity / 配信 / Webhook / ファイル）。
    - ファイルの型・サイズ・権限。
  - web: アクションシートとタブの状態。
- **E2E**（`e2e/spec.mjs`）: 390 × 844 で次を確かめる。
  - 下のタブで 5 か所を行き来する。
  - 長押しシートでリアクションする。
  - 画像を添付して送り、相手の画面で表示されることを見る。
  - グループ DM を作る。
  - 非公開チャネルを作り、メンバーでない人に見えないことを見る。
