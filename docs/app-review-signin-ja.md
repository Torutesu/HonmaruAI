# 審査員がサインインできるようにする（日本語）

App Store の審査は、実際に人がアプリを触ります。サインインが必要なアプリで
その人が中に入れないと、**必ず差し戻されます**。理由は「アプリを確認できな
かった」で、コードの良し悪しは一切見てもらえません。

やることは 2 つだけです。**アカウントは作成済み**なので、実質 1 つです。

---

## 前提の確認

先に、これがあるか見てください。無いと先へ進めません。

- **Apple Developer Program のメンバーシップ**（年 99 ドル）
  <https://developer.apple.com/programs/> — 加入していないと App Store Connect
  にアプリを作れません。
- **App Store Connect にアプリが登録済み**であること
  <https://appstoreconnect.apple.com> → **マイ App**（My Apps）に
  「Honmaru AI」が並んでいれば OK。

アプリがまだ無い場合は、**マイ App** の左上の **＋** → **新規 App** で作りま
す。聞かれるのは次の 4 つです。

| 項目 | 入れるもの |
| --- | --- |
| プラットフォーム | iOS |
| 名前 | Honmaru AI |
| バンドル ID | `com.honmaru.ai` |
| SKU | 何でもよい（例：`honmaru-ios`）。社内管理用の文字列で、誰にも見えません |

---

## 手順

### 1. App Store Connect を開く

<https://appstoreconnect.apple.com> にサインイン。

### 2. アプリを開く

**マイ App**（My Apps）→ **Honmaru AI** をクリック。

### 3. バージョンのページに入る

左側のメニューに、こういう行があります。

```
iOS App
  └ 1.0  提出準備中        ← これをクリック
```

英語表示なら `1.0 Prepare for Submission` です。

> **この行が無い場合**：まだバージョンが作られていません。左メニューの
> 「**＋ バージョンまたはプラットフォーム**」から `1.0` を追加してください。

> **左サイドバーの「App Review」ではありません。** 紛らわしいのですが、
> あちらは*提出したものが並ぶ履歴のページ*で、初回は
> 「Items you submit to App Review will appear here.」と出るだけです。
> 入れたいのは**バージョンのページの中**なので、必ず
> `1.0 提出準備中` の行から入ってください。

### 4. ページの一番下までスクロールする

長いページです。スクリーンショット、説明文、キーワード……とずっと下に進むと、
最後のほうに **App Review 情報**（App Review Information）という見出しが
あります。

### 5. 「サインインが必要」にチェックを入れる

**サインインが必要**（Sign-In Required）というチェックボックスです。
チェックを入れると、ユーザ名とパスワードの入力欄が出てきます。

### 6. これを入れる

| 欄 | 入れる値 |
| --- | --- |
| **ユーザ名**（User Name） | `appreview@honmaruai.com` |
| **パスワード**（Password） | セッションで発行したもの（この文書には書きません） |

### 7. 「メモ」欄にこれを貼る

同じ **App Review 情報** の中に、**メモ**（Notes）という自由記述欄があります。
ここに貼ってください。**英語で書きます**（審査員は英語話者です）。

```
To sign in:
1. Tap "Sign in with email" on the first screen.
2. Tap "Use a password instead" at the bottom of the sheet.
3. Enter the account above.

A GitHub account is not required and GitHub sign-in is not offered in this app.
```

**この 3 行が重要です。** アプリを開くと最初に見えるのは「メールでサインイン」
で、パスワードの入口はその 1 つ下の階層にあります。メモが無いと、審査員が
そこに辿り着けずに差し戻される可能性があります。

### 8. 保存する

ページ右上の **保存**（Save）を押します。押し忘れると入力が消えます。

## よくある詰まりどころ

**「App Review 情報」が見つからない**
左メニューの **App Review** を開いていませんか。そこは提出履歴で、別物です。
`1.0 提出準備中` の行をクリックし、**そのページを**一番下まで下がってください。

**入力欄がグレーで触れない**
そのバージョンが審査中か、すでに配信済みです。審査中なら
「**審査を中止**（Cancel Submission）」してから編集できます。

**保存できない**
同じページの必須項目（スクリーンショット、説明文、プライバシーポリシー URL
など）が埋まっていないと保存を拒否されることがあります。エラーの出ている
項目を先に埋めてください。

## このアカウントについて

- **メールは一切届きません。** パスワードで入るアカウントなので、
  このアドレス宛の受信設定は不要です。
- 個人ワークスペースが 1 つ付いています。審査員には**空のフィード**が見え
  ます。それでも審査は通りますが、カードが数枚あったほうがアプリの意図は
  伝わります。
- パスワードを変えたくなったら、同じ手順で別のアカウントを作って差し替えて
  ください（作り方は
  [app-store-review-readiness.md](app-store-review-readiness.md) にコマンドが
  あります）。

---

## これで足りないもの

デモアカウントは**審査は通せますが、実ユーザーは通せません**。

招待した人にサインインコードを届けるには、Resend でドメイン認証が要ります。
今は Resend アカウントの持ち主のアドレスにしか届きません。そちらは
[app-store-review-readiness.md](app-store-review-readiness.md) を見てください。
