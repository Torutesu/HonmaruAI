# Honmaru AI リリース候補レビュー — 2026-09-08

対象: `main` の `76ce3a1` から作成した `codex/release-ui-modernization`。
この資料は候補コードの検証記録です。本番デプロイ、App Store / TestFlight 配信、実機での外部サービス連携が済んだことを示す資料ではありません。

## UIで変えたこと

既存の白い画面、濃いCTA、AIにだけ使う紫という方向を維持し、読みやすさと状態の分かりやすさを改善しました。Figmaの `470:282` は画像化されたホーム参照として取得できました。今回は既存構成を活かした刷新であり、Figmaの全画面との完全一致は検証対象ではありません。

| Before | After | Why |
| --- | --- | --- |
| Webの汎用ログイン画面と全画面フィード | 製品の用途が分かるログイン画面、受信・送信・完了・記録のワークスペース | 最初の利用と日々の判断を迷わず進めるため |
| iOSで入力欄と利用上限表示が通常シェルから隠れる | テキスト入力欄と必要な状態表示を常設 | 録画や長押しに依存せず依頼できるようにするため |
| 固定ページ高さと文字サイズ制限 | 自然な高さでスクロールするカードとDynamic Type対応 | 長い内容も読め、操作に到達できるようにするため |
| ダークモードで薄いボタンに白文字 | 背景と対になるCTA文字色 | 操作の可読性を維持するため |
| ゲストでも「オフライン」だけ表示 | ゲスト・切断・アクセス拒否・空の受信箱を区別 | 状況と次にできることを伝えるため |
| スワイプ必須の初回チュートリアル | 承認・却下ボタンと明示的な「次へ」 | スワイプが難しい人も初回設定を完了するため |
| サーバーに拒否されても端末の見た目だけ成功 | エラー表示とサーバー状態の再取得 | 反映されていない判断を成功に見せないため |

## 修正したリリース上の問題

### バックエンド

- 認証前のWebSocketへの組織データ配信を停止。
- 接続済みでもセッションの失効と現在の組織所属を確認。
- 同一IDのカード作成による既存カードの上書き、送信者の書き換え、削除済みカードの復活を防止。
- 非同期の翻訳・事業分類は対象フィールドだけを更新し、その間に行われた判断を巻き戻さない。
- 古い形式で休止していた接続は再接続させ、新しい認証確認へ移行。

### iOS

- 通信断や一時的なサービスエラーでログイン情報を消去しない。
- 未送信操作をユーザー・組織・接続先ごとに永続化し、失敗した先頭操作と後続操作を保持。
- ログアウト・組織変更中に完了した古い通信が、新しいセッションへ書き込まない。
- 認証済みスナップショットを受け取るまで「接続済み」にしない。
- 空のサーバースナップショットを反映し、削除済みカードをキャッシュに残さない。
- サーバーの操作拒否を画面に伝え、楽観的に表示していたカードを再同期。

### Web

- サーバーから作成カードの反映を受け取ってから送信完了を扱う。
- 送信タイムアウト・切断・拒否を表示し、入力内容を保持。
- 古い接続・途中のAI応答がログアウト後や別の組織へ反映されない。
- シート表示中のショートカット、キャンセルされたタッチ操作でカードを処理しない。
- 完了履歴と取り消し、再読み込み時のセッション復元を検証。

## 依存関係

Web: Vite 8.2.2 / React plugin 6.1.1 / Vitest 4.1.11。
Worker: Vitest 3.2.6 / Cloudflare pool 0.12.21 / Wrangler 4.72.0。
Node 20.19以降または22.12以降が必要です。

公開アドバイザリと互換性を確認して更新しました。参照: [Vitestの修正情報](https://github.com/advisories/GHSA-5xrq-8626-4rwp)、[Wranglerの修正情報](https://github.com/cloudflare/workers-sdk/security/advisories/GHSA-36p8-mvp6-cv38)、[Cloudflareのテストランタイム互換性](https://developers.cloudflare.com/workers/testing/vitest-integration/migration-guides/migrate-from-vitest-3-to-vitest-4/)。全依存パッケージに脆弱性がないことを保証する監査ではありません。

`npm audit` は依存情報の外部送信として自動承認レビューに拒否されたため実行していません。代替として公開アドバイザリを確認し、インストールでは監査送信を無効にしました。

## 配信前に残る確認

- 最終候補をレビュー・マージし、Workerのデプロイ結果と対象コードを確認する。
- 署名済みiOSアーカイブをTestFlightに配信し、実機でGitHubログイン、複数ユーザーの送受信、再接続、カメラ・音声・コネクタ連携を確認する。
- ネイティブAPNsは既存設定で無効。本番healthも `push:false`。有効化するならApp ID、プロビジョニング、entitlement、クライアント設定を揃える。
- ネイティブのWebSocket送信完了はD1永続化の受領証ではない。今回、既知の消失・スコープ混在・拒否の不可視化を修正したが、切断と永続化の境界での厳密な一度だけの配送は未保証。
- ログアウトはクライアントの状態を消去する。サーバー側セッションを即時に失効するログアウトAPIは既存仕様にない。
- GitHub上の権限変更はD1所属情報の更新後に効く。組織内のカードは現在の仕様どおり組織メンバー間で共有される。
- 旧形式の `outbox.json` は所属情報がないため自動再送せず保持する。別のチームへ誤送信しないことを優先した移行境界。

実行手順は [shipping.md](../../shipping.md)、[app-store-release.md](../../app-store-release.md) を参照してください。
