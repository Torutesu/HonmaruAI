# Honmaru AI

SwiftUI iOS app plus a Node relay server. Humans talk to their AI; agents route
Decision Cards across the org in real time.

## Layout

| Path | What |
|------|------|
| `HonmaruAI/` | iOS app sources. Generated project — edit `project.yml`, not the `.xcodeproj` |
| `server/` | Node relay: WebSocket fan-out, GitHub OAuth token swap, OpenRouter proxy |
| `Config/Base.xcconfig` | Build settings. `Local.xcconfig` (gitignored) overrides `RELAY_HOST` |
| `scripts/` | Device demo, App Store Connect setup, release pipeline |

The Xcode project is generated by xcodegen. After changing `project.yml` or
adding a source file, run `xcodegen generate`. Never hand-edit `.xcodeproj`.

## Running it

### Simulator

```bash
cd server && npm start        # leave running in another tab
xcodegen generate && open HonmaruAI.xcodeproj
```

Loopback is the default, and on the simulator the Mac is the host, so this works
with no extra configuration.

### On a physical device

On a phone `127.0.0.1` is the phone, so the app must be pointed at the Mac's LAN
address. `scripts/device.sh` handles it:

```bash
scripts/device.sh            # detects the Mac's Wi-Fi address, rewrites the build config
cd server && npm start       # another tab
```

Then in Xcode: select the iPhone as the destination and press Run. Both machines
must be on the same Wi-Fi, and the phone will ask for local network permission
on first launch — it must be allowed or the relay is unreachable.

`scripts/device.sh --reset` returns to loopback for the simulator.

## Things that will bite

- **The relay address is baked in at build time.** Changing Wi-Fi networks
  changes the Mac's address; re-run `scripts/device.sh` and rebuild.
- **Plain `ws://` on the LAN only works because of `NSAllowsLocalNetworking`**
  in `Info.plist`. It exempts private ranges only. A publicly hosted relay must
  be `wss://`.
- **`//` starts a comment in an xcconfig**, which is why `RELAY_SCHEME` and
  `RELAY_HOST` are separate settings joined in `Info.plist`.
- **Target build settings outrank xcconfigs.** Putting `RELAY_HOST` under
  `settings:` in `project.yml` would silently break `scripts/device.sh`.
- **`DEVELOPMENT_TEAM` is deliberately empty in `project.yml`** so the repo
  carries no personal account id. `scripts/release.sh` injects it from
  `.asc.env`; an Xcode GUI build needs it set in Signing & Capabilities, and
  that selection is lost on the next `xcodegen generate`.
- **The app icon must have no alpha channel.** Xcode rejects the asset catalog
  at archive time even when every pixel is opaque.

## Releasing

```bash
scripts/setup.sh                 # one-time: writes .asc.env
scripts/release.sh doctor        # auth, signing, review readiness
scripts/release.sh build 0.1.0   # xcodegen -> archive -> ipa
scripts/release.sh testflight
```

Full guide: `docs/app-store-release.md`. Japanese walkthrough for non-engineers:
`docs/setup-ja.md`.

App Store review is still blocked — see the blocker list in `PROGRESS.md`. The
main one is that the relay is not hosted anywhere, so a reviewer cannot sign in.

## Conventions

- Swift: `Design/Theme.swift` holds spacing, radius and color tokens. Use them
  rather than literals.
- Services are plain classes under `Services/`, injected through `AppState`.
- The server is dependency-light on purpose: `ws` is the only runtime dependency.
